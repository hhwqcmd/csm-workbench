# 架构决策

本文件只记录仍影响当前实现的架构取舍。具体真实调用结果见
[`validation-log.md`](./validation-log.md)，原始共学过程见已归档的
[`tutorial-roadmap.md`](./tutorial-roadmap.md)。

## D001：官方 Python 基线与 Web 产品隔离

- **状态**：有效
- **决定**：保留 `official-quickstart/` 作为官方 SDK 基线，Web 产品在 `app/` 独立演进。
- **原因**：便于对照官方协议、隔离运行时依赖，并在 Web 适配失败时保留最小验证路径。
- **约束**：`app/` 不导入 Python 文件；修改官方示例只改解压副本，不改原 ZIP。

## D002：所有真实调用经过同源服务端适配

- **状态**：有效
- **决定**：Seedance 浏览器只调用 `/api/seedance/tasks` 和 `/status`；Managed Agents 只调用 `/api/managed-agents/*`。各自服务端模块校验并转发。
- **原因**：避免浏览器直连上游造成 Key 暴露，同时集中执行 Base URL、模型、素材和能力限制。
- **约束**：服务端不是通用代理；Seedance 只允许标准 API 与 Agent Plan 两个精确地址，Managed Agents 只允许标准 API。

## D003：同时支持标准 API 与 Agent Plan

- **状态**：有效，2026-07-24 从单一 Agent Plan 方向修订
- **决定**：页面提供两条路径；当前默认是标准 API + Seedance 2.0 Mini。
- **原因**：既能演示官方日期版本模型，又能验证 Agent Plan 套餐别名和计费通道。
- **约束**：Key、Base URL 与模型 ID 必须按路径成套切换。

## D004：演示凭证与任务历史只做设备本地持久化

- **状态**：有效，Seedream 活跃任务短期状态由 D022 形成例外
- **决定**：Key 按路径、最近 30 条任务及结构化日志保存到当前浏览器 `localStorage`。
- **原因**：保持单机演示与跨设备隔离；生成历史和凭证不进入服务端数据库。
- **约束**：日志中的 Authorization 必须掩码；该记录不是服务端审计。D022 允许 D1 暂存 Seedream 活跃任务，D024 允许 D1 保存不含凭证和签名 URL 的素材元数据；两者都不能扩展为任务历史或凭证存储。

## D005：任务采用异步创建与显式重调度轮询

- **状态**：有效
- **决定**：创建后每 30 秒查询状态，使用 `pollCycle` 安排下一轮。
- **原因**：上游可能连续多次返回相同 `running` 状态，只依赖 React 状态变化会停止轮询。
- **约束**：临时查询错误继续重试；终态才停止；活跃任务期间锁定连接配置。

## D006：示例和模板共用一个任务执行器

- **状态**：有效
- **决定**：官方示例和模板资产都通过 `seedance:apply-example` 预填 `SeedanceTaskRunner`。
- **原因**：确保展示值、完整 Request Body、费用确认、创建、历史和日志不会形成两套实现。
- **约束**：预填本身不创建任务；缺素材模板保留空 URL，并在补齐前阻止执行。

## D007：连续视频严格串行

- **状态**：有效
- **决定**：每段请求 `return_last_frame: true`，取得上一段 `last_frame_url` 后才创建下一段。
- **原因**：下一段首帧依赖上一段结果，无法安全并发。
- **约束**：任一段失败或缺少尾帧即停止；每段单独进入历史与日志。

## D008：暂不启用 D1/R2

- **状态**：部分被 D022 取代；R2 仍未启用
- **决定**：保留 `db/`、`drizzle/` 和示例代码，但不接入当前产品。
- **原因**：现阶段只需要设备本地恢复，服务端持久化会扩大数据、认证与运维边界。
- **修订**：Seedream 同步生成无法在浏览器刷新后继续，因此 2026-08-05 启用最小 D1 任务表；2026-08-06 又因素材需跨浏览器长期恢复，由 D024 增加素材元数据表。R2 仍不启用。
- **重新评估条件**：出现跨设备历史、团队审计、共享模板或托管素材需求。

## D009：产品采用公开 Sites 访问

- **状态**：已被 D023 取代；2026-07-28 至 2026-08-06 有效
- **决定**：生产 Sites 公开直达，不在应用入口要求登录。
- **原因**：降低演示访问门槛；凭证仍由每位访问者在自己的浏览器输入和保存。
- **约束**：`app/chatgpt-auth.ts` 维持未使用遗留状态；重新启用认证必须作为独立架构变更评估。

## D010：Managed Agents 作为独立顶级工作台

- **状态**：有效，2026-07-28 生效
- **决定**：Managed Agents 与演示工作台、模板资产库并列，内部使用“管理 Agent → 配置 Agent 环境 → 管理 Session”三步工作流和独立本机历史。
- **原因**：Managed Agents 是资源创建与 SSE 会话协议，不应挤入视频异步任务表单；独立页面更适合完整讲解。
- **约束**：标准官方 Key 与 Seedance 共用，但请求状态、资源 ID 和历史不混入视频任务记录。

## D011：Session 事件必须先建立 SSE 再发送

- **状态**：有效
- **决定**：浏览器先通过同源 `session-events` 路由建立上游 SSE，再通过第二次同源请求发送用户事件。
- **原因**：官方事件流只推送连接建立后产生的事件；先 POST 再 GET 可能漏掉早期 Agent 与状态事件。
- **约束**：Key 仍不得进入 URL；收到 `session.status_idle` 后客户端主动结束读取；日志分别记录 GET 流和 POST 事件；旧 `messages` 兼容路由也必须遵循同一顺序。

## D012：Agent 管理采用一个结构化编辑器覆盖 Create 与 Update

- **状态**：有效，2026-07-29 生效
- **决定**：Managed Agents 第 1 步统一命名为“管理 Agent”，用模式切换生成 `POST /agents` 或 `POST /agents/{agent_id}`；基础字段、Skills、Tools、MCP、Multi Agent、metadata 与右侧 Request Body 双向联动。
- **原因**：CreateAgent 与 UpdateAgent 共享同一 Agent 定义，但更新额外受版本并发控制、部分更新和 Skills 覆盖语义约束；拆成两套页面容易产生字段和协议漂移。
- **约束**：创建默认模型为 `doubao-seed-evolving`；Skills、Tools、MCP、Multi Agent 默认不传入并按需展开；更新必须带当前 `version`；服务端不接受未知字段；MCP Server 与 Toolset 一一对应；创建/更新响应在步骤内直接展示并写入日志；自动化验证使用模拟上游，不因切换模式创建真实资源。

## D013：Agent 环境以云环境全字段编辑器呈现

- **状态**：有效，2026-07-29 生效
- **决定**：Managed Agents 第 2 步统一命名为“配置 Agent 环境”，完整呈现 `name`、`description`、云端类型、网络策略、六类依赖包、环境变量、metadata 与预留 scope；表单、Request Body 和 API 响应在同一步内联动。
- **原因**：环境不仅是名称和网络开关，它同时决定 Session 可访问的网络、预装依赖和运行时变量。完整展示能让演示者在创建前解释实际沙箱边界，也与“管理 Agent”的交付结构保持一致。
- **约束**：当前工作台只开放官方指引中的 `cloud` 环境；`allow_mcp_servers`、`allow_package_managers` 和 `allowed_hosts` 只允许在 `limited` 网络模式出现；环境变量不得使用 `ARK_`、`VOLC_` 保留前缀；环境没有版本机制，变更通过创建新环境完成；自动化测试不得创建真实环境。

## D014：Session 生命周期与事件统一为一个管理环节

- **状态**：有效，2026-07-29 生效
- **决定**：原“开启会话”和“发送消息并流式传输响应”合并为“管理 Session”，通过模式切换覆盖创建、检索、列出、事件与流、永久删除。
- **原因**：Session 是一个有状态生命周期资源，创建和消息只是其中两类操作；统一呈现更适合解释状态机、检查点、检索、用量与删除边界。
- **约束**：不提供官方尚未支持的 Session 更新；创建支持最新/固定 Agent 版本和可选 Vault；删除要求显式不可逆确认且 running 不可删除；检索/列表/删除不伪造 Request Body；事件严格校验顺序并先开流；自动化验证只使用模拟上游。

## D015：文件与 Memory 作为 Session 上下文资源统一呈现

- **状态**：有效，2026-07-29 生效
- **决定**：在“管理 Session”中增加“文件与挂载”“持久化记忆”模式；Files API 上传、Session Resources、Session 关联文件、Memory Store 与 Memory 内容均使用专用同源路由，并允许在创建 Session 的 `resources[]` 组合 file、TOS 与 memory_store。
- **原因**：文件与 Memory 最终都作为沙箱目录供 Agent 读取，但生命周期不同：文件可在运行中增删，Memory Store 只能创建时挂载；统一呈现能说明关联关系，同时避免把 `file_id`、`resource_id`、`memory_store_id` 混为一谈。
- **约束**：Files 上传固定 `purpose=agent`；运行时只允许动态添加 file；TOS key 必须是目录；单 Session 最多 100 个文件与 10 个 Store；Memory 对 Agent 只读，单条 100 KB、单 Store 2,000 条；所有真实写入和删除必须由用户显式执行，自动化测试只使用模拟上游。

## D016：Seedream 采用独立顶级工作台并按能力适配模型

- **状态**：有效，2026-07-30 生效
- **决定**：Seedream 与演示工作台、模板资产库、Managed Agents 平级；十类教程示例共用一个图片编辑器、完整 JSON、结果、历史和日志实现。默认使用 `doubao-seedream-5-0-pro-260628`，仅在 Pro 官方未支持的组图、联网与流式示例中切换为 Lite。
- **原因**：图片同步生成、组图 SSE 和 Prompt 优化与视频异步任务的协议不同，强行复用 `SeedanceTaskRunner` 会混淆状态和能力；同时所有图片示例共用一个执行器可避免表单、完整 Request Body 与实际请求分叉。
- **约束**：故事书/连环画附录不进入产品；浏览器不直连上游；服务端采用字段与模型能力白名单；Prompt 一键优化固定调用 `doubao-seed-evolving` 并使用场景技巧；真实图片生成要费用确认，测试只模拟上游。

## D017：Responses API 采用场景编辑器与完整协议目录双层呈现

- **状态**：有效，2026-07-30 生效
- **决定**：Responses API 与现有栏目平级；八类场景共用一个结构化表单、完整 JSON、API 详情、响应、SSE、历史和日志执行器，另以请求字段、响应字段和联合类型目录完整呈现官方协议。
- **原因**：只做参数百科不便于演示，只做少数表单又会遗漏复杂联合结构；“高频表单 + 完整 JSON + 协议目录”既能讲场景，也能审核实际请求。
- **约束**：只使用标准 `/api/v3`；浏览器不直连上游；创建、查询 Input Items 与删除均经同源代理；真实创建需费用确认，删除需不可逆确认；服务端拒绝未知顶层字段、危险 URL 和缓存冲突；自动化测试只使用模拟上游。

## D018：七个顶级栏目共用演示优先的导航与视觉节奏

- **状态**：有效，2026-08-05 更新
- **决定**：顶级栏目固定按“模板资产库 → Seedance → Seedream → Responses API → Managed Agents → LLM 趋势 → AI coding”排列；无 Hash 时进入模板资产库，旧 `#sample` / `#operations` 深链继续进入 Seedance。桌面端显示序号和当前位置，窄屏改为七等分短标签。
- **原因**：现场演示需要讲解者随时确认所在模块，并在投屏和窄屏下保持首屏完整。原导航在中等宽度信息拥挤，移动端多行换行还会让哈希定位内容被粘性顶部栏遮挡。
- **约束**：视觉层只调整布局和呈现，不改变各模块的请求状态、凭证、费用确认、API 路由或本机历史；七个入口必须保持键盘可达，窄屏不得产生横向页面滚动。

## D019：LLM 趋势采用有日期的静态研究快照

- **状态**：有效，2026-07-31 生效
- **决定**：LLM 趋势与现有栏目平级；Seed、Seedance、Seedream 分模态呈现，文本模型只保留每家最新可核验旗舰，并围绕价格、参数、编程、长程与 Agent 指标展开。Arena 和 Artificial Analysis 作为独立信号，不与厂商 benchmark 混成总榜。
- **原因**：价格、模型代际和榜单名次都会快速变化，自动抓取又会引入来源漂移、服务可用性与部署网络依赖。有日期、可追溯的静态快照更适合稳定演示和人工复核。
- **约束**：厂商官网 / 官方模型卡优先；未披露的参数和价格不估算；原币种不强制换算；不同 benchmark 不直接横向排名；页面不得自动调用模型、付费 API 或第三方榜单。

## D020：AI coding 采用产品中立的最佳实践与模拟指标

- **状态**：有效，2026-08-03 生效
- **决定**：AI coding 与现有栏目平级，四个承载栏目仍按“Agent 资产管理 → 项目资产 → 代码质量 → AI 效能度量”组织；栏目内部以存量接口变更演示“规格 → 知识 → 计划 → 护栏执行 → 验收 → 回流”的完整闭环。页面不展示具体 AI coding 产品名，前三部分只呈现方法、模板与证据，效能区使用模拟组织、部门与同源只读指标 API。
- **原因**：企业演示需要传递可迁移的团队工程系统，而不是产品功能清单或个人 Prompt 技巧；同时研发效能数据通常涉及员工、代码与组织敏感信息，直接接入真实平台会扩大隐私、认证与数据治理边界。
- **约束**：八类 Agent 资产必须完整呈现；知识必须说明来源、Owner、时效与失效条件；质量链路保留人工最终审查；效能区展示 AI 代码行数、AI 代码入库率、Skill 使用率、MCP 使用率、Token 消耗量 TOP 3 与需求交付周期 P50。代码量和 Token 只用于规模与成本观察，不得独立作为效能或绩效结论；模拟数据必须显式标注，不得接入真实身份、Prompt、代码内容或生产指标系统。

## D021：私有 TOS 保存文件，本机浏览器保存素材索引

- **状态**：已被 D024 取代；2026-08-05 至 2026-08-06 有效
- **决定**：Seedance 视频、Seedream 图片和手动上传的三类文件写入固定 TOS bucket 的 `demo/{video|image|audio}/`；桶保持私有，服务端使用 TOS4 签名上传并生成短时 GET 地址。页面只在当前浏览器保存对象键、名称、类型、大小、时间、来源与来源标识。
- **原因**：生成结果 URL 有时效，文件需要独立沉淀；同时当前需求明确不做跨设备共享索引，因此无需启用 D1/R2 或列举 TOS。
- **约束**：AK/SK 只在服务端环境；不保存原始生成 URL和预签名 URL；清空浏览器数据会丢失页面索引但不会删除对象。本地写接口仍不鉴权并可能产生 TOS 存储与流量费用；类型、大小、SSRF 和固定路径校验不是身份鉴权。当前不提供删除或反向恢复。

## D022：Seedream 生成使用 24 小时可恢复后台任务

- **状态**：有效，2026-08-05 生效
- **决定**：费用确认后由 `/api/seedream/jobs` 先创建任务并让浏览器保存匿名任务 ID 和恢复令牌，再以独立 `run` 请求执行长调用；刷新后继续查询同一任务。D1 只保存恢复令牌哈希、状态、URL 格式结果、脱敏错误和过期时间，24 小时后清理。
- **原因**：Seedream 上游是同步或 SSE 图片生成，浏览器直接持有请求时刷新会中止本地等待，重新点击又可能造成重复计费。短期任务状态可以在不引入账号体系和永久历史的前提下恢复同一次生成。
- **约束**：API Key、Prompt、参考图、完整 Request Body 和浏览器历史不得写入 D1；后台任务只接受 `response_format=url`；恢复令牌只存当前浏览器，其他设备不可见；页面加载与状态查询不得创建新生成；自动化测试只模拟上游和 TOS。

## D023：测试阶段仅在本地开发并暂停 Sites 发布

- **状态**：有效，2026-08-06 生效
- **决定**：当前项目只在本地开发、调试和验证；短期内不把本地代码保存或部署到 Sites。既有 Sites 站点保留历史版本，但访问范围收紧为仅项目所有者。
- **原因**：项目仍处于测试阶段，需要先稳定本地功能、数据边界和验证流程，避免把在途代码或真实写接口继续暴露到托管环境。
- **约束**：保留 `.openai/hosting.json` 的既有项目 ID，不创建、替换或更新托管版本；只有用户后续明确恢复 Sites 发布时，才重新评估访问策略、环境变量、持久化数据和发布验证。

## D024：D1 持久索引与 TOS 目录对账

- **状态**：有效，2026-08-06 生效
- **决定**：素材文件继续保存在私有 TOS；D1 保存 `MaterialAsset` 长期索引。素材库加载时分页列举 `demo/{video|image|audio}/`，补建缺失记录并清理已不存在对象的索引；升级前的浏览器缓存经 TOS HEAD 校验后可补写 D1。修改名称只更新 D1；删除经二次确认后先删除 TOS，再删除 D1。
- **原因**：浏览器 localStorage 受访问域名、端口和站点数据影响，无法保证隔日或跨浏览器恢复；TOS 文件本体与持久元数据必须共同作为素材库事实来源。
- **约束**：浏览器缓存不是主数据；预签名 URL 保持 1 小时且不得进入 D1、localStorage 或日志。TOS 目录列举使用服务端 Header 签名，列举和删除只允许固定素材前缀；列举权限不足时必须保留 D1/缓存并告警，目录缺项也必须以 HEAD 404 复核后才能清理索引。自动化测试只使用模拟 TOS/D1。当前无账号隔离，恢复 Sites 发布前必须新增或重新确认访问控制。
