# 架构决策

本文件只记录仍影响当前实现的架构取舍。具体真实调用结果见
[`validation-log.md`](./validation-log.md)，原始共学过程见已归档的
[`tutorial-roadmap.md`](./tutorial-roadmap.md)。

## D001：官方 Python 基线与 Web 产品隔离

- **状态**：有效
- **决定**：保留 `official-quickstart/` 作为官方 SDK 基线，Web 产品在 `app/` 独立演进。
- **原因**：便于对照官方协议、隔离运行时依赖，并在 Web 适配失败时保留最小验证路径。
- **约束**：`app/` 不导入 Python 文件；修改官方示例只改解压副本，不改原 ZIP。

## D002：所有真实调用经过同源服务端适配

- **状态**：有效
- **决定**：Seedance 浏览器只调用 `/api/seedance/tasks` 和 `/status`；Managed Agents 只调用 `/api/managed-agents/*`。各自服务端模块校验并转发。
- **原因**：避免浏览器直连上游造成 Key 暴露，同时集中执行 Base URL、模型、素材和能力限制。
- **约束**：服务端不是通用代理；Seedance 只允许标准 API 与 Agent Plan 两个精确地址，Managed Agents 只允许标准 API。

## D003：同时支持标准 API 与 Agent Plan

- **状态**：有效，2026-07-24 从单一 Agent Plan 方向修订
- **决定**：页面提供两条路径；当前默认是标准 API + Seedance 2.0 Mini。
- **原因**：既能演示官方日期版本模型，又能验证 Agent Plan 套餐别名和计费通道。
- **约束**：Key、Base URL 与模型 ID 必须按路径成套切换。

## D004：演示凭证与任务历史只做设备本地持久化

- **状态**：有效
- **决定**：Key 按路径、最近 30 条任务及结构化日志保存到当前浏览器 `localStorage`。
- **原因**：满足单机演示刷新恢复，不引入账号体系、D1 或跨设备同步。
- **约束**：服务端不持久化；日志中的 Authorization 必须掩码；该记录不是服务端审计。

## D005：任务采用异步创建与显式重调度轮询

- **状态**：有效
- **决定**：创建后每 30 秒查询状态，使用 `pollCycle` 安排下一轮。
- **原因**：上游可能连续多次返回相同 `running` 状态，只依赖 React 状态变化会停止轮询。
- **约束**：临时查询错误继续重试；终态才停止；活跃任务期间锁定连接配置。

## D006：示例和模板共用一个任务执行器

- **状态**：有效
- **决定**：官方示例和模板资产都通过 `seedance:apply-example` 预填 `SeedanceTaskRunner`。
- **原因**：确保展示值、完整 Request Body、费用确认、创建、历史和日志不会形成两套实现。
- **约束**：预填本身不创建任务；缺素材模板保留空 URL，并在补齐前阻止执行。

## D007：连续视频严格串行

- **状态**：有效
- **决定**：每段请求 `return_last_frame: true`，取得上一段 `last_frame_url` 后才创建下一段。
- **原因**：下一段首帧依赖上一段结果，无法安全并发。
- **约束**：任一段失败或缺少尾帧即停止；每段单独进入历史与日志。

## D008：暂不启用 D1/R2

- **状态**：有效
- **决定**：保留 `db/`、`drizzle/` 和示例代码，但不接入当前产品。
- **原因**：现阶段只需要设备本地恢复，服务端持久化会扩大数据、认证与运维边界。
- **重新评估条件**：出现跨设备历史、团队审计、共享模板或托管素材需求。

## D009：产品采用公开 Sites 访问

- **状态**：有效，2026-07-28 生效
- **决定**：生产 Sites 公开直达，不在应用入口要求登录。
- **原因**：降低演示访问门槛；凭证仍由每位访问者在自己的浏览器输入和保存。
- **约束**：`app/chatgpt-auth.ts` 维持未使用遗留状态；重新启用认证必须作为独立架构变更评估。

## D010：Managed Agents 作为独立顶级工作台

- **状态**：有效，2026-07-28 生效
- **决定**：Managed Agents 与演示工作台、模板资产库并列，内部使用四步顺序工作流和独立本机历史。
- **原因**：Managed Agents 是资源创建与 SSE 会话协议，不应挤入视频异步任务表单；独立页面更适合完整讲解。
- **约束**：标准官方 Key 与 Seedance 共用，但请求状态、资源 ID 和历史不混入视频任务记录。

## D011：Managed Agents 消息由同源路由组合 POST 与 SSE

- **状态**：有效
- **决定**：浏览器向同源消息路由发一次 POST；服务端先向上游提交 `user.message`，再连接 `/events/stream` 并转发响应体。
- **原因**：保持 Key 不在浏览器直连上游，同时复刻官方“先发送、后监听”的协议顺序。
- **约束**：收到 `session.status_idle` 后客户端主动结束读取；日志分别记录发送请求与事件流结果。
